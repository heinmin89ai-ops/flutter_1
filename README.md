# Workshop Ops

Production-oriented Flutter foundation for an offline-first, multi-tenant car workshop management system.

## Current phase

Phase 14 testing and production readiness is implemented on top of the Phase 13 foundation with:

- Flutter and Functions CI workflow
- Firebase Auth, Firestore, Functions, and Storage emulator configuration
- SQLite migration contract and sync idempotency coverage
- Focused unit/widget test commands and security test scenarios
- Deployment and production rollout checklist
- Role-authorized workshop reports for jobs, invoices, payments, balances, and low stock
- Server-side report aggregation with date-range validation
- Active-account enforcement in callable functions and Firestore/Storage rules
- Append-only audit log helper for sensitive actions
- Tenant-scoped Storage rules for vehicle/job photos and PDF documents
- Additional Firestore composite indexes for report queries
- SQLite sync queue with pending, syncing, failed, and completed states
- Local-first customer and vehicle writes with automatic retry on connectivity return
- Idempotency keys, exponential backoff, stale-sync recovery after app restart, and bounded retries
- Receipt printer abstraction, ESC/POS encoder, discovery/connect/print/disconnect contract
- Real sync status in the application shell instead of a simulated status toggle
- POS invoice creation for labor, parts, services, and direct sales
- Integer minor-unit subtotal, discount, tax, total, and balance calculations
- Cash, card, bank transfer, mobile payment, and other payment methods
- Transactional partial and multiple payments with append-only payment records
- Server-side invoice total and payment balance validation
- Inventory items, low-stock indicators, and stock movement UI
- Transactional stock-in, stock-out, adjustment, and return operations
- Integer minor-unit inventory prices
- Warranty creation for completed jobs with 1, 3, 6, or 12-month options
- Server-calculated warranty expiry and tenant-protected warranty history
- Job-card creation with customer complaint and priority
- Role-aware job-card state machine
- Transactional server-side status transitions
- Mechanic assignment checks for repair-work updates
- Manager/owner mechanic assignment action with active same-tenant validation
- Job-card list filtered to assigned work for mechanics
- Tenant-scoped job-card rules and indexes
- Customer and vehicle registration
- UUID identifiers generated before synchronization
- Local SQLite vehicle cache and indexed license-plate search
- Plate normalization for spaces, hyphens, and casing differences
- Tenant-scoped customer and vehicle Firestore rules
- Super Admin workshop onboarding through a trusted callable function
- Shop Owner staff listing, creation, activation, and deactivation
- Server-side role and custom-claim management
- Tenant-scoped Firestore reads and restrictive Firestore rules
- Firebase email/password sign-in and session restoration
- Claims-based role and workshop validation
- Sign-out and account menu
- Firebase-independent widget test wiring
- Material 3 application shell
- Responsive navigation for phone and tablet layouts
- Workshop dashboard surface
- Explicit online, offline, syncing, and pending-change states
- Feature-first project boundaries
- No secrets or environment-specific Firebase values in source control

Firebase must be configured for each target before running the app. On Android and iOS, add the platform configuration generated by FlutterFire. The app reads `shopId`, `role`, `permissions`, and `isActive` from Firebase Auth custom claims; it never accepts those values from the login form.

Deploy the backend from the project root after installing the Firebase CLI and functions dependencies:

```bash
cd functions
npm install
npm run build
cd ..
firebase deploy --only functions,firestore:rules
```

Flutter SDK was not available in the development environment when this phase was created, so runtime verification is still required locally.

## Run

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```
